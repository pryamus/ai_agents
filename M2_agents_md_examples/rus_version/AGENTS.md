# Область проекта (Project Domain)

Это REST API для просмотра и управления коллекцией автомобилей. Каждый автомобиль представляет собой полную запись с уникальным `id`, который присваивается сервером, а также полями `make` (марка), `model` (модель), `year` (год выпуска), `horsepower` (мощность в л.с.), `engine_cc` (объем двигателя в куб. см) и `transmission` (коробка передач).

Поле `engine_cc` может быть равно `0` для полностью электрических автомобилей. Каждый возвращаемый или сохраняемый вами автомобиль должен содержать все поля.

## Настройка и управление проектом

- **Версия Python:** 3.12. Не используй более новый синтаксис.
- **Управление зависимостями:** Используй `uv` и `pyproject.toml`. Никогда не используй `pip` или файл `requirements.txt`.
- **Добавление зависимостей:** Используй команду `uv add <package>`. Никогда не используй `uv pip` для управления зависимостями.
- **Запуск приложения:** Используй команду `uv run fastapi dev main.py`.
- **Работа с ветками:** Создавай ветки от `main` с именем `feature/<name>` и используйте Conventional Commits.
- **Проверка изменений:** Подготавливай stage для код-ревью. Не делай коммиты в ветку `main` и не отправляй изменения на удаленный сервер (push) без соответствующей просьбы.

## Соглашения по коду

- Указывай аннотации типов (type-hints) для публичных функций и методов, включая типы возвращаемых значений.
- Используй модуль `pathlib` для работы с путями. Не используй `os.path`.
- Отдавай предпочтение f-строкам вместо `str.format()` или форматирования через `%`.
- Придерживайся принципа EAFP: обрабатывайте исключения вместо предварительной проверки условий.
- Пиши doc strings в стиле Google для каждой публичной функции и метода.
- Валидируй тела запросов с помощью моделей Pydantic.
- Используй идиоматичный Python, такой как comprehensions, генераторы и декораторы.

## Структура проекта

- Структура проекта плоская: файл `main.py` содержит приложение, а файл `cars.json` — данные.
- Файл `main.py` является единственным модулем для редактирования при добавлении новых функций.
- Размещай тесты в файле `tests/test_main.py`.
- Не создавай новые пакеты или файлы без соответствующей просьбы.

## Критерии качества (Quality Gates)

Задача считается выполненной только в том случае, если пройдены все следующие проверки:

- Команда `uv run ruff format` оставляет код без изменений.
- Команда `uv run ruff check` не находит ошибок.
- Команда `uv run mypy main.py` не находит ошибок.
- Команда `python -m py_compile main.py` возвращает статус код равный 0.
- Тесты `uv run pytest` проходят успешно, при этом для каждой новой конечной точки (endpoint) добавлен тест.

## Ограничения

- Спрашивай разрешение перед добавлением любой внешней зависимости.
- Сохраняй сигнатуру и структуру ответов существующих конечных точек.
- Не используйте блокирующий ввод-вывод (I/O) внутри асинхронных (`async`) функций.
- Сохраняй существующие тесты в нетронутом виде и исправляйте код так, чтобы они проходили.
- Объявляй задачу выполненной только после прохождения всех проверок качества и обновления докстрингов.

## Игнорировать

Все файлы и папки, указанные в `.gitignore`, закрыты для чтения и редактирования. Кроме того, никогда не открывай:

- Секреты и файлы `.env`.
- Большие файлы данных, не связанные с текущей задачей.
- Сторонний (vendored) или сгенерированный код.
