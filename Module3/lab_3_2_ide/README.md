# Лабораторная 3.2 — Связка IDE + агент + инструменты

**Цель:** окружение как проверяемый артефакт: doctor ставит диагноз
(проверка + подсказка + exit-код), IDE-конфиги генерируются и валидируются
кодом, а не правятся руками вслепую.

## Структура

```text
lab_3_2_ide/
├── doctor.py  # проверки python/pytest/ruff/git/opencode (+node опционально)
├── ide.py     # init/check для .vscode/{settings,tasks,extensions}.json
└── tests/test_ide.py
```

## Шаги практики

1. **Диагноз окружения:**

   ```powershell
   cd code\lab_3_2_ide
   python doctor.py
   python doctor.py --json --md-out env.md
   ```

   Exit 0 — всё обязательное на месте; иначе список «не хватает» с рецептами.

2. **Конфиги как код (на копии проекта, не в самом репозитории!):**

   ```powershell
   python ide.py init --dir C:\tmp\demo_ws
   python ide.py check --dir C:\tmp\demo_ws
   ```

3. **Тесты:**

   ```powershell
   python -m pytest -q
   ```

4. **(Самостоятельно)** Сломайте `tasks.json` (удалите задачу `ruff`)
   и покажите, что `check` находит именно её. Добавьте задачу `validate`
   под свой каталог лаборатории.

## Ключевые решения

- **Проверка = диагноз + рецепт:** каждая строчка doctor'а содержит hint —
  иначе проверка превращается в «красный крест без лечения».
- **Required vs optional:** отсутствие node не роняет exit-код; отсутствие
  git — роняет. Градация честнее бинарного «ок/не ок».
- **Задачи IDE = команды курса:** `pytest`, `ruff`, `validate` — те же
  строки, что в AGENTS.md; один источник истины для рук и автоматики.
