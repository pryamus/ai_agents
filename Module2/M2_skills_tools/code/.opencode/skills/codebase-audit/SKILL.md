# Codebase audit

Скилл описывает ПРОЦЕДУРУ (когда и в каком порядке применять инструменты),
само описание инструментов в промпт подставляет рантайм из реестра.
Skills ≠ Tools: скилл — инструкция, инструмент — исполняемая функция.

## Когда использовать

- «найди все места, где используется устаревший метод/TODO»;
- «проверь, ничего ли я не сломал перед коммитом»;
- задачи ревью, где сначала нужен поиск, потом статическая проверка.

## Workflow

1. `grep_search` — найти кандидатов: точный литерал или `use_regex=true`
   (например `pattern="deprecated|obsolete"`, `use_regex=true`).
2. Для каждой находки `path:line` — открыть контекст прочтением файла
   (не гадать по одной строке).
3. `ruff_lint` — проверить найденные файлы: замечания линтера приложить
   к отчётности (это данные, а не ошибка).
4. Перед предложениями правок — `git_diff`: убедиться, что работа идёт
   поверх чистого (или осознанно изменённого) дерева.

## Правила вывода

- каждая находка: `path:line | цитата строки | предлагаемое действие`;
- сортировать по severity: сломанное — выше косметики;
- если инструмент вернул ошибку `invalid_args` — исправить аргументы по
  тексту ошибки и повторить ОДИН раз; при `timeout`/`runtime` — не
  долбить, а сообщить человеку.

## Ограничения

- не выходить за корень проекта (path-аргументы валидируются реестром);
- не запускать `git push` и не трогать ветки — только чтение diff.
